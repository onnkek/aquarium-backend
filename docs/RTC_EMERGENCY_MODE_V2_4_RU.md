# v2.4 — RTC fail-safe emergency mode

Если RTC недоступен, батарейка села, DS3231 потерял питание или время выглядит невалидным,
прошивка автоматически переводит аквариум в emergency mode.

## Почему

Расписания реле и автодозатор зависят от времени. Если время неверное, система может:

- включить CO2 не в тот период;
- запустить дозатор повторно/не вовремя;
- некорректно управлять нагревом/охлаждением;
- неправильно применить расписания.

Поэтому при невалидном RTC запрещена нормальная автоматика.

## Что считается невалидным RTC

RTC считается невалидным, если:

- `rtc.begin()` не смог найти DS3231;
- `rtc.lostPower()` вернул true;
- год меньше 2024 или больше 2099.

Год 2000 считается невалидным, потому что это типичное состояние после сброса/севшей батарейки/невыставленного RTC.

## Что делает emergency mode

Emergency mode не выключает всё подряд. Он сохраняет жизнеобеспечение:

| Узел | Состояние |
|---|---:|
| CO2 | OFF |
| Heat | OFF |
| Cool | OFF |
| Doser 1..4 | OFF |
| O2 | ON |
| Filter | ON |
| Light / охлаждение светильников | ON |
| ARGB | ON, red |

## Как увидеть состояние

```bash
curl -s $ESP/api/health
```

В ответе:

```json
{
  "status": {
    "rtc": false,
    "emergencyMode": true
  }
}
```

Также в `/api/current`:

```bash
curl -s $ESP/api/current
```

появляется блок:

```json
{
  "safety": {
    "emergencyMode": true,
    "rtcValid": false
  }
}
```

## Как выйти из emergency mode

Автоматического выхода нет. Это специально.

Если RTC снова стал валидным, пользователь должен проверить причину аварии и затем восстановить нужные режимы через API/фронт.

Время можно выставить через существующий endpoint `/api/time`.
